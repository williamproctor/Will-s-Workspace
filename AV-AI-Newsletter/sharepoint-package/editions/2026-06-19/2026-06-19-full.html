This Week in AI

Adobe Firefly AI Assistant Moves Into the Creative Apps

Adobe's June 18 update is one of the clearest examples yet of AI assistants moving from standalone prompt surfaces into the applications where creative work already happens.

Adobe announced that AI Assistant, powered by its creative agent, is now in public beta across Premiere, Photoshop, Illustrator, InDesign, and Frame.io. The assistant had already existed in Firefly, but this expansion changes the context. Instead of asking an AI tool to generate an isolated asset, users can now interact with an assistant inside the working app, next to the files, bins, layouts, and review surfaces that already hold production context.

For Premiere, Adobe and coverage around the launch describe tasks such as:

  • Sorting assets into bins.
  • Batch-renaming clips.
  • Identifying interview questions.
  • Adding markers.
  • Helping move raw footage toward a structured first cut.

That is not the same as a model generating an entire finished video. It is more practical and more important: AI is being pointed at the repetitive organizing and first-pass work that surrounds editing. In Frame.io, the relevance is also obvious. Review, comments, versions, approvals, and project context are already there. Adding an assistant to that environment signals Adobe's intent to make agentic help part of the review and production layer, not only the generation layer.

Adobe also previewed an upgraded Firefly creative AI studio in private beta. The new studio is meant to connect generation and editing in one place, with Projects for storing context and assets, and Elements for reusing generated characters, objects, and locations across work. Adobe also described new skills including storyboard-to-video, product-video creation, and Quick Cut, which can assemble raw footage into a structured first cut that a person can refine.

The pattern is consistent with the past month of AI video news: the market is moving away from "type a prompt, get a clip" and toward persistent creative workspaces. Adobe's advantage is that its workspace is already where many production files live. The open question is how well the assistant handles real project complexity, but the direction is clear. AI assistance is becoming an operating layer inside creative software.

Google Vids Adds Longer Veo Clips and Parallel Generation

Google updated Google Vids on June 17 with two Veo-related features: longer generated clips and parallel generation.

The first update lets users extend existing Veo clips into longer videos while preserving storytelling continuity and character consistency. The second lets users start multiple video-generation requests at the same time, which makes prompt and style comparison faster than waiting for one generation to finish before starting the next.

Google says the rollout applies across a broad set of Google Vids users, including Workspace Business and Enterprise editions, Education Plus, nonprofits, personal Google accounts, Google AI Pro and Ultra users, and several add-on categories. The rollout began June 17 for both Rapid Release and Scheduled Release domains, with feature visibility expected within one to three days.

The AV relevance is not that Google Vids suddenly replaces an NLE. It does not. The point is that lightweight workplace video tools are absorbing more of the AI video workflow: generate a clip, extend it, compare variants, add music, record a screen, assemble a presentation-style video, and share it inside the same ecosystem.

That matters because not every AV-adjacent video is a full production. Some work is internal explanation, training support, project communication, or rough visualization. Google Vids is moving into that middle layer: more capable than a slide deck, less specialized than Premiere or Resolve.

Palmier Pro: A Video Editor Built for Agents

Palmier Pro launched through Y Combinator as an open-source, Mac-native video editor built for AI agents. The pitch is direct: Claude, Codex, Cursor, or an in-app assistant can operate the project timeline through a local MCP server.

Palmier's own README describes the app as a video editor where "you and your agent can generate and edit videos together inside the timeline." When the app is open, it exposes an MCP server at:

``text

http://127.0.0.1:19789/mcp

`

Agents can connect to that local endpoint and interact with the project. The workflow is different from sending a prompt to a remote generator. The agent can see the timeline, understand tracks and clips, and make edits in the working project.

The core idea has two parts:

  • AI video as a timeline primitive. Generated images, video, audio, prompts, models, and references are tracked inside the project rather than handled as separate downloads.
  • Timeline access through MCP. External agents can trim, reorder, organize, generate, and edit with project context.

Palmier Pro is currently macOS-only, requires macOS 26 on Apple Silicon, and the editor plus MCP server are open source under GPLv3. Generative processing is the closed component. That split is interesting: the app and agent interface are inspectable, while the generation backend remains a service.

For AV workflows, Palmier is important less because it is a mature replacement for existing editors and more because it shows a new interface pattern. Instead of AI sitting beside the editor, AI is given structured access to the editor. That is the same MCP pattern showing up across development tools, now applied to a timeline.

LTX Trainer Makes Open Audio-Video Models More Customizable

Lightricks followed last week's LTX-2 open audio-video story with a more technical but important update: LTX Trainer, a unified training framework for LTX-2.

The trainer supports several modes from a shared framework:

  • Standard LoRA training.
  • Audio-video LoRA training.
  • IC-LoRA for video-to-video transformations.
  • Full model fine-tuning.

LTX's announcement frames the trainer as one framework for every training mode, covering video, audio, and cross-modal conditioning. The GitHub documentation is more specific: the trainer package provides tools and scripts for LoRA training, full fine-tuning, and video-to-video transformations on custom datasets. Audio-video LoRA can be enabled by setting with_audio: true in the training strategy.

The practical meaning is that LTX-2 is not only open as a model. It is becoming open as a customization stack. That is the difference between an open model people can run and an open model people can adapt.

There are real constraints. The standard LTX-2 trainer documentation recommends Linux with CUDA and an Nvidia GPU with 80GB+ VRAM for standard configs, with lower-VRAM options available through memory optimizations. Full fine-tuning can require multiple high-end GPUs and distributed training. This is not casual desktop editing.

Still, for the direction of the market, the update matters. Closed models compete on immediate quality and convenience. Open models compete on control, local operation, customization, and pipeline ownership. LTX Trainer pushes the open side further toward serious production and research workflows.

Mistral Voxtral TTS Adds Another Voice Model to the Stack

Mistral's Voxtral TTS is not brand new this week in the strictest sense — Mistral's official post dates to March — but it re-entered the news cycle this week through broader coverage of voice models and Mistral's audio stack. It is worth including because the details are directly relevant to the voice-agent and narration landscape.

Voxtral TTS is a 4B-parameter multilingual text-to-speech model supporting nine languages:

  • English
  • French
  • German
  • Spanish
  • Dutch
  • Portuguese
  • Italian
  • Hindi
  • Arabic

Mistral positions Voxtral TTS for low-latency voice-agent applications. The official post lists 70ms model latency for a typical input with a 10-second voice sample and 500 characters, and an API price of $0.016 per 1,000 characters through /v1/audio/speech. The model natively generates up to two minutes of audio, with longer output handled through API interleaving.

The research paper and Hugging Face page add another important detail: Voxtral TTS can adapt to a voice from as little as 3 seconds of reference audio. The open-weight Hugging Face release includes preset reference voices under a non-commercial license, while broader custom voice cloning remains tied to the API.

For AV teams, the model adds another option to the already crowded voice stack. ElevenLabs remains a major incumbent. OpenAI has the realtime voice layer. Mistral is positioning Voxtral as a compact, multilingual, low-latency TTS option with both API and open-weight paths.

The bigger pattern: voice generation is splitting the same way video generation is splitting. Some tools optimize for studio-quality narration, some for realtime agents, some for multilingual cloning, and some for local/open-weight experimentation.

Adobe on the Human Role in Agentic Creative Work

Adobe's June 18 announcement framed its creative agent as a tool that handles multi-step execution while the person keeps creative direction:

"choosing what to hand off to the assistant, what to own and how best to apply their taste, expertise and judgment to shape every editable outcome."

That is a useful sentence because it avoids the common "AI replaces the artist" framing. Adobe is describing a division of labor: the assistant can organize, rename, assemble, and prepare; the human still owns taste, judgment, and the final editable outcome.

Palmier on Letting Agents Operate the Timeline

Palmier's launch framed the product around a simple idea:

"Palmier Pro is a video editor built for AI, where Claude and Codex can edit your timeline directly."

The significance is not the specific app alone. It is the interface model. The timeline becomes something an agent can read and manipulate through a structured protocol, rather than a black box that only a person can operate manually.

Zeev Farbman on Open Audio-Video Models

Lightricks co-founder and CEO Zeev Farbman framed LTX-2 as an openness and control story:

"LTX-2 is the first truly open audio-video model, released with open weights and training code, and designed to run locally on consumer GPUs."

He also said:

"It delivers the kind of quality and performance teams usually associate with closed systems, without giving up control, transparency, or the ability to customize."

That is the same reason LTX Trainer matters this week. Open weights are useful, but training code and customization paths are what turn an open model into a production pipeline candidate.

Simon Willison on Fable 5's Early Feel

Developer Simon Willison described Claude Fable 5 as "slow, expensive" while also saying it was capable enough that the challenge was finding tasks it could not handle.

That matches the broader reaction: Fable 5 is not being treated as a cheap everyday model. It is being treated as a high-ceiling model for hard, long-running work where the added cost and latency can make sense.

Common Threads

The Assistant Is Moving Into the Working File

Adobe's assistant in Premiere and Frame.io, Palmier's MCP-accessible timeline, and Mosaic-style agentic editing tools all point to the same shift. AI assistance is moving closer to the file where work actually happens. The model does not just answer a question; it sees the project, the bins, the clips, the comments, or the timeline.

First Cuts Are Becoming a Software Layer

Adobe's Quick Cut, Google Vids' clip extension, Mosaic's agentic editing, and Palmier's timeline agent all touch the same middle layer of production: rough assembly, ordering, finding, trimming, marker placement, and first-pass structure. None of these replaces a finished edit. But the rough-cut layer is clearly becoming a target for automation.

Open Models Need Open Tooling

LTX-2 was already notable because it paired audio and video generation with open weights. LTX Trainer makes the point sharper: open models matter more when teams can adapt them. Training tools, LoRA paths, and documented customization pipelines are part of the capability, not just extras around it.

Frontier Models Are Splitting by Workload

Claude Fable 5 shows the split between daily models and hard-task models. Faster, cheaper models are still better for summaries, drafts, and routine transformations. More capable models earn their place when the task is long, complicated, and likely to compound errors if the first few steps go wrong.

Novel Ideas Worth Watching

MCP for Media Timelines

MCP has already become familiar in coding and agent workflows. Palmier Pro shows what happens when the same concept is applied to media editing. A timeline can expose actions and state to an agent: read tracks, inspect clips, trim, reorder, add generated assets, or place markers. If that pattern spreads, "agent-compatible editor" could become a real category.

Persistent Creative Context

Adobe's Projects and Elements preview is another sign that creative AI systems are trying to remember project context across generations. A reusable character, object, location, brand style, or project context is more useful than a one-time generation. Continuity is becoming a product feature.

Audio Models as Infrastructure, Not Just Narrators

Voxtral TTS, ReSing Doubling, ElevenLabs Avatars, and OpenAI Realtime all point to audio models becoming infrastructure layers. Voice is not only narration. It can be a realtime interface, a localization layer, a draft-performance layer, or a production effect.

Tip of the Week

Back to Basics, Week 4: Tell It What Not to Change

Last week, the Back to Basics series covered show, don't tell: examples often work better than abstract instructions.

This week is about the other half of reliable prompting: tell the model what not to change.

Most people give AI the revision task but forget the preservation rules. That creates a common problem: the output looks cleaner, but something important changed. A timecode disappears. A name is altered. A safety instruction gets softened. A Scripture reference, if present in source material, is paraphrased when it needed to stay exact. A caption correction gets rewritten as a summary instead of staying tied to the original line.

The model is trying to be helpful. If the instruction is "make this better," it may assume everything is negotiable.

Add a preservation block:

`text

Your task: revise this script for clarity and pacing.

Preserve exactly:

  • All names and titles.
  • All timecodes.
  • Any safety instructions.
  • Any quoted language.
  • The three-section structure.
  • The target runtime of 90 seconds.

You may change:

  • Sentence length.
  • Transitions.
  • Repeated wording.
  • Jargon that can be simplified.

Return:

1. Revised script.

2. Brief list of what changed.

``

For AV work, preservation rules are especially useful because the source material often contains constraints:

  • Timecodes
  • Speaker names
  • Caption wording
  • Runtime limits
  • Technical terms
  • File names
  • Review-note categories
  • Safety or compliance language
  • Stakeholder-approved wording

The weekend exercise: take one prompt you already use for revision and add two blocks: Preserve exactly and You may change. The model will usually become more careful because it knows which parts of the task are fixed and which parts are flexible.
